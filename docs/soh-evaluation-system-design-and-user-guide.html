项目概览

系统以可比较、可追溯、可复核的算法测评为第一目标，并以跨数据集、跨电芯和跨化学体系的多场景算法建设为第二目标。它不是只展示一个误差数字的看板，而是把输入、协议、执行覆盖、逐样本预测、指标和发布物连成可验证证据链。

阅读路径只用于突出推荐章节，不会隐藏任何正文。管理者可优先阅读概览、架构、公平测评和证据结论；研发人员可继续阅读领域方法与核心契约；工具使用者可从前端、资源接入和运行章节开始。

为什么可信

可信不来自界面上的“通过”颜色，而来自每一步都绑定前一步摘要。候选源码、模型和数据首先变成内容引用；RunSpec 固化比较口径；PredictionRecord 保留样本身份但不向候选暴露测试真值；Metrics 记录贡献样本和聚合范围；EvidencePack 再对发布所依赖文件逐项登记大小和 SHA-256。

SOH 数据、特征与算法原理

发现契约与结构语义

已接入领域能力从 D:\battery_SOH\data\processed\*_features.pkl 发现处理后特征表。Pickle 只在受信本机环境读取，本文不嵌入其内容。当前发现数量必须以 GET /api/catalog 和前端目录的实时结果为准，不在说明书中固定。

字段结构性意义质量要求
dataset数据来源/语义域，参与数据集级分组与跨域协议。不得用同名掩盖不同来源、化学体系或标签定义。
cell_id电芯或资产身份，是 LOCO、轨迹聚合和泄漏检查的基本单位。同一实体必须稳定；训练与测试身份不得交叠。
cycle_index资产内的循环/观测顺序，用于轨迹、因果特征和时间前推。检查重复、逆序、跳变和重置语义。
soh监督真值，标签公式由数据卡/LabelSpec 解释。必须为有限值；只允许 Metric Worker 连接测试真值。

入场质检至少检查：必需列缺失、soh 为 NaN/Inf 等非有限标签、同一电芯重复周期、轨迹顺序异常、每个数据集的样本/电芯覆盖，以及训练/测试身份或派生统计交叉造成的泄漏。样本多不等于电芯覆盖充分；统计有效单位应优先服从独立资产，而非把同一电芯的循环当作独立重复。

特征方案

方案输入侧重点适用与限制
full声明允许的通用统计与领域特征。覆盖较广，但必须经 FeaturePolicy 排除标签、未来信息和仅部分数据域可得的代理变量。
voltage充电电压统计、形状和固定窗口摘要。易解释；受协议、电流、温度和采样密度影响。
ic_dvaIC/DVA 峰位、峰高、面积和形状摘要。对老化机理变化敏感；微分会放大噪声，需明确平滑和窗口。
partial_window只使用可部署的局部充电电压窗口。适合浅充或数据不完整场景；不同化学体系的平台区不可直接复用同一窗口。
capacity_time窗口容量、充电时长和相关速率。直观且样本效率高；依赖电流积分、阶段识别和时间单位一致性。

领域原理与泄漏边界

固定充电窗口：在同一电压区间比较充电容量、持续时间和曲线形状，可降低完整充电终点不一致带来的影响。窗口必须由化学体系和可观测协议预先声明，不能在看见测试误差后逐电芯选择。

IC/DVA：增量容量 IC 通常写作 dQ/dV，突出容量随电压变化的峰；微分电压 DVA 写作 dV/dQ，突出电压对容量变化的响应。二者都需要排序、去重、重采样与平滑；平滑参数只能在训练折或预先固定，不能利用完整测试轨迹调参。

健康指标三性：相关性衡量候选 HI 与 SOH/退化趋势的关联；单调性衡量方向一致程度但允许真实恢复和噪声；鲁棒性衡量局部扰动相对长期趋势的大小。三者是特征筛查证据，不等同于预测准确率或因果解释。

因果平滑与折内计算：部署时第 k 个循环不能读取未来循环，因此滚动、滤波和重标定应使用当前及历史数据。所有填充、缩放、特征筛选、平滑参数、校准和 FeatureState 必须在训练/校准折内拟合，再原样应用于 held-out 视图。

算法族与责任边界

算法族归纳偏置优点限制适用样本规模
线性/正则化特征作用近似加性、平滑且低复杂度。稳定、透明、训练快，适合作为必备基线。难表达强交互和分段退化。小到中等；高维时需正则化与折内选择。
树模型以分段常数和特征交互逼近非线性。适合表格特征、尺度不敏感、可处理交互。域外外推弱，可能学习数据集/周期代理。中等；小样本需控制深度和叶节点。
核方法在相似度空间进行平滑非线性回归。小样本下可表达平滑曲面。对尺度/核参数敏感，样本增大时训练和内存成本上升。小到中等。
神经网络通过表示学习拟合高维或序列模式。可消费曲线/序列并共享跨任务表示。数据与算力要求高，调参空间大，复现实验需严格固定。中到大；小样本须强基线和消融。
物理残差先验模型给出主趋势，学习器只拟合系统性偏差。可提高可解释性并约束域外行为。先验错误会传递；残差目标和基准模型必须可审计。小到中等，取决于先验质量。
PINN把物理方程或单调/边界惩罚写入损失。可联合数据拟合与软约束。权重敏感、优化困难；“带物理损失”不自动证明物理正确或优于经典模型。中到大；需要独立验证约束收益。

责任边界：点估计器负责 y_pred；不确定度模块负责区间与 PICP；后处理负责范围、平滑或单调政策；周期重标定使用目标域已授权标签并属于 Adaptation Run。四者必须分别登记，不能把组合效果归因成单一算法能力。

方法与公开数据资源综述

数据驱动方法：公开项目常见路线包括手工循环特征配合线性/树/核回归，以及直接学习充放电序列的 MLP、CNN、RNN 或 Transformer。项目资料显示，经典表格模型应保留为强基线，深度模型的价值需在完全相同的切分、输入和统计单位下验证，不能从模型复杂度推断领先。

混合物理方法：SOHbenchmark 提供 XJTU/MIT 的多输入基准背景；PINN4SOH 展示把退化约束与神经网络联合的路径；本项目另有物理残差、范围门和轨迹约束。它们的共同价值是显式写出先验，但必须报告先验、数据项和后处理各自贡献。

不确定度方法：多 seed 波动描述训练随机性，预测区间描述样本条件不确定度，两者不可互换。项目使用共形校准等模块时，应以留出资产形成校准证据，并同时报告覆盖率 PICP 与区间宽度；若校准使用目标电芯早期标签，则应归类为 Adaptation Run，而非 Frozen Inference Run。

公开数据差异：NASA PCoE、CALCE、Oxford Battery Degradation Dataset、XJTU/MIT（SOHbenchmark）、HUST、Sandia SNL/BatteryArchive、UConn-ISU-ILCC 等资源覆盖 LFP、NMC/NCM、LCO/NCA 等不同体系与圆柱/软包等形态。恒温实验、动态工况、倍率/DOD/温度矩阵和现场浅充浅放并非同一任务；采样频率、RPT 间隔、充放电阶段、额定或初始容量归一化、标签插值和 EOL 口径也不同。因此同名 SOH、同名数据组织项目甚至同名机构数据都不能默认可合并或直接比较。

可核验的项目/作者参考包括：Microsoft BatteryML；Wang Fujin 等的 SOHbenchmark 与 PINN4SOH；Ruifeng Tan 等的 BatteryLife；Toyota Research Institute BEEP；Sandia BatteryArchive；NASA PCoE；CALCE；Oxford Battery Degradation Dataset；Ma 等的 HUST 数据；Preger 等的 SNL 研究；Nowacki 等的 UConn-ISU-ILCC 数据。这里列名称用于方法与数据边界定位，不作 SOTA 排名，也不显示出版年份。

公平测评协议与指标

协议定义

协议留出边界回答的问题主要风险
LOCOLeave-One-Cell-Out，整颗电芯留出。同数据来源内对未见电芯的泛化。电芯数量少时方差大；同批次/同协议仍可能过于相似。
LODOLeave-One-Dataset-Out，整套数据来源留出。跨设备、采样、工况或机构的数据域迁移。标签定义与输入 schema 不一致可能使任务不可比。
LCHOLeave-One-Chemistry-Out，整类化学体系留出。跨 LFP、NMC/NCM、LCO/NCA 等体系的外推。化学体系常与形态/协议共变，结论需避免错误因果归因。
运行类型允许动作禁止混淆
Training Run在训练折拟合特征状态和模型，产出新的 ModelArtifact。不得查看 held-out 真值或用全量数据预计算特征。
Adaptation Run基于声明的目标域校准子集派生新模型/偏置/区间，并记录成本与谱系。不得覆盖基础模型，也不得把适配结果标成零样本迁移。
Frozen Inference Run冻结模型与 FeatureState，只在未见快照上执行 transform/predict 和性能计时。不得 fit、微调、周期重标定或利用目标测试标签。

公平比较的共同前提

  1. 同 DatasetSnapshot：字节摘要、清洗规则、标签和样本身份一致。
  2. 同协议：LOCO/LODO/LCHO、fold 生成规则和 held-out 单位一致。
  3. 同 seed 集：随机性真实注入估计器、采样器和初始化路径；不能只在元数据里改数字。
  4. 同 held-out 覆盖：尝试、成功、失败的执行单元分母一致，失败不能从均值分母中消失。
  5. 同特征拟合边界：填充、缩放、选择、平滑、校准和超参数只从相应训练/校准视图学习。

只有 TaskSpec、DatasetSnapshot、ProtocolSpec、MetricSpec 和 PolicySpec 构成的 comparison key 一致，候选才可进入同一正式比较。候选本身、run type、seed 或幂等请求可不同，但不能借此改变共同任务口径。

指标与统计单位

指标含义解读边界
MAE绝对误差平均值，单位与 SOH 一致。直观但不突出少量大误差。
RMSE平方误差均值开方。对大误差更敏感；不可与 MAE 数字直接排名。
MAPE相对真值的绝对百分比误差。真值接近零时不稳定，必须声明分母政策。
偏差带符号平均误差。正负误差会抵消，应与 MAE/RMSE 联读。
最大误差最差样本绝对误差。对离群点敏感，但能暴露高风险失败。
PICPPrediction Interval Coverage Probability，真值落入预测区间的比例。覆盖高不代表区间好；必须同时报告平均宽度。
单调性轨迹方向一致程度或违反率。真实容量恢复可能存在，不能机械要求严格下降。
越界率预测超出 PolicySpec 允许 SOH 范围的比例。后处理截断后的值不能掩盖原始越界证据。
EOL达到退役阈值的周期/时间误差或分类判断。依赖阈值、插值和截尾政策，需单独声明。

轨迹级：先在单一电芯随循环的序列上计算误差、单调性、EOL 和区间覆盖，保留时间结构。资产级：每颗电芯先形成统计量，再等权或按预声明权重聚合，并可做资产 bootstrap。数据集级：汇总资产分布、覆盖和最差域；不能让长轨迹仅凭循环多而支配结论。

排行资格与失败处理

  • 完整覆盖：所有必需组合成功、证据有限且比较键一致，才可按 PolicySpec 进入正式排行。
  • 部分成功：至少一个单元成功且至少一个失败；必须显示 attempted/succeeded/failed 和失败类别，默认不产生正常验收 verdict，也不能与完整覆盖候选等价排序。
  • 失败组合：全失败、超时、资源耗尽、NaN 或证据不完整均保留为一等结果，不能删行后重算均值。
  • 不具可比性：快照、协议、指标版本、特征预算或 held-out 覆盖不同的结果分榜展示，不发布“更优”结论。

核心契约与证据对象

RunSpec -> DatasetSnapshot -> target-stripped fold view -> fitted FeatureState -> ModelArtifact -> PredictionRecord -> Metrics -> EvidencePack -> Publication

对象职责

RunSpec
不可变地引用 task、dataset、protocol、metric、policy 和候选内容，并记录 run type、seeds 与幂等键。comparison key 只由共同任务口径生成，使候选变化不改变比较组，而快照、协议、指标或政策变化必然分组。
DatasetSnapshot
固定输入表、样本身份、schema、来源/标签谱系和内容 digest。重新扫描目录不应悄悄改变既有运行；新字节产生新快照引用。
Target-stripped fold view
算法可见的 held-out 输入中不含 soh 或可逆推出真值的字段。训练标签只进入训练侧 fit；Metric Worker 用 sample_id 在内部连接真值。这是核心泄漏边界。
FeatureState 与 ModelArtifact
FeatureState 保存仅由训练/校准折拟合的填充、缩放、选择或平滑状态及其摘要；ModelArtifact 保存模型字节、输入 schema、来源运行和所引用 FeatureState。Frozen Inference Run 只能消费，不能覆盖。
PredictionRecord
至少绑定 run、candidate、featureset、protocol、fold、seed、dataset、cell、cycle 和 sample 身份，并要求 y_pred 等数值为有限实数。执行/样本键不得重复；测试真值不是候选输出要求。
Metrics
记录指标名/版本、值、单位、方向、aggregation_scope、贡献 sample_ids 与 cell_ids。有限值、区间顺序和重复身份均在写入证据前验证。
EvidencePack
manifest 固定 run identity、comparison key 和产物列表；每个产物记录相对路径、大小和 SHA-256。写入采用独占临时文件、刷新后原子替换；读取时重新验证路径、大小和摘要，篡改或缺失即失败。
Publication
只有验证通过且满足资格政策的证据才能形成发布视图。当前文件发布使用不可变 generation、CURRENT.json 和 last-known-good 思路，避免半成品覆盖活动版本。

状态、结果与裁决必须分离

execution_state 描述生命周期位置；outcome 描述执行单元完成结果；verdict 描述政策/人工是否接受发布。运行结束、全部算完和可以发布是三个不同事实。

新资源接入

四类资源均先进入 staging，完成格式、契约和冒烟验证后再激活。replace 缺省为 false；失败事务恢复原文件、目录和目录项，但系统没有面向用户的“撤销任意已成功上传”历史 API。

1. 数据集表

接受 .csv、.pkl、.pickle 或 .parquet。推理必需列是 dataset、cell_id、cycle_index；训练还必须有 soh。cycle_index 必须是 0 到 int64 上限内的有限整数，表不能为空。

上传后 dataset 被规范为逻辑名，文件原子发布到 processed/{name}_features.pkl。先以目标模式验证列，再激活，避免把无标签推理表误用于训练。

2. 算法源码插件

文件必须是 .py，暴露 Estimator、get_estimator() 或 PLUGIN['estimator'] 返回的类；类必须实现 fit() 和 predict()。上传时会实例化并做有限预测/区间冒烟测试。

源码插件会被编译并在 API 进程内执行，不受沙箱保护。获得上传权限等价于获得本机代码执行权限，只接入已审查的可信源码。

3. 特征方案源码插件

文件必须是 .py，提供列选择和/或可调用的 transform。变换结果必须仍是 DataFrame、行数不变，声明的候选列必须存在。

Runner 为每个 fold 克隆流水线，只在训练视图上 fit FeatureState，再用同一状态变换 held-out 视图。拟合状态不得跨 held-out 边界复用或提前查看测试标签。

4. 冻结模型包

模型是 .pkl/.pickle，manifest 文件名必须为 model_manifest.json。必需键为 model_name、model_kind、feature_columns、target、predict_contract；model_kind 必须为 pickle，特征列不得为空，模型必须有 predict()。

不受信任的 Pickle 在反序列化时可以执行代码。模型上传与源码插件同属 trusted-local 边界，不能作为互联网匿名上传格式。

训练矩阵与耗时估算

请求体为 {datasets?, estimators?, featuresets?, protocols?, seeds?}，缺省分别是 all、ridge、full、loco、[0]。实际训练执行单元数不是简单的数据集数量乘法，而是：

执行单元数 =
  所选协议实际生成的 fold 总数
  × 每个算法的有效特征迭代数
  × seed 数

普通算法：有效特征迭代数 = 所选 featureset 数
BYO 算法：有效特征迭代数 = 1 个 “(byo)” pipeline

每个执行单元都拟合模型并预测 held-out 数据；LSTM/CNN/Transformer 默认迭代多个 epoch，PINN 默认更多 epoch。因此大量 fold、seed 和深度模型会使任务长时间 running。当前任务没有细粒度进度百分比或取消 API，应通过任务状态、进程资源和最终产物判断，不要重复点击启动。

训练完成与模型发布

每个无执行错误且可快照的 fold 会保存 fitted estimator、特征列与 FeatureState、训练数据范围、held-out key、协议、seed、run ID 和 predict(X, meta=None) 契约。模型包先序列化、重新加载并冒烟预测，再进入资产库；模型发布失败会成为 model_warnings，不会伪装成已发布。

冻结推理请求与部分成功

请求至少需要 models，可带 datasets、审计字段和非空 pairs。后端为每个模型-数据集对恢复 manifest 声明的特征流水线状态，检查缺失列，然后执行预测。模型读取失败或特征不兼容只生成受影响组合的失败记录；有成功也有失败时任务终态为 partial。

任务历史、轮询与重跑

训练历史来自 GET /api/jobs，推理历史来自 GET /api/inference-jobs；详情路由附加任务 ID。前端约每秒轮询，瞬时错误会退避重连，404 会清除活动锁并允许重跑。终态只有 succeeded、partial、failed；重跑创建新任务、新 run ID 和新 generation，不原位改写旧运行。先从历史恢复相同选择，再根据失败列/模型缩小范围重跑。

结果、排行与证据解释

单个 KPI 不是结论。先核对任务终态和 execution coverage，再核对 comparison key、数据范围、指标、验收 verdict 与证据摘要。

类别文件用途解释边界

KPI、覆盖与验收通过

  • 可比最佳 MAE：只在当前筛选后仍有有限 MAE 且覆盖可比较的条目中选择；数值小不代表覆盖完整。
  • execution coverage：succeeded / attempted；0 表示没有成功执行单元，1 表示执行覆盖完整，但仍不自动代表业务验收通过。
  • 验收通过：前端统计 leaderboard 中现有 verdict 布尔项的通过数/总数。只有 required acceptance metrics 在成功执行单元中完整、有限时才生成 verdict。
  • 零可以是有效显示：若没有可形成终态验收裁决的记录，后端保留空 verdicts，前端可显示 0/0。这表示“无可计数 verdict”，不是“所有算法都失败”。

数据集筛选语义

全选时使用 aggregate leaderboard；子集选择必须过滤 dataset_leaderboard.json 的 held-out 数据集记录并重新聚合 metrics 与 verdicts。筛选不能只改标题、芯片或样本数。多 seed 稳定性摘要当前仍是全量聚合，不随局部筛选变化，界面会明确提示。

数据同步与离线打包

发布采用 staging → 校验 → fsync → generation → 原子更新 CURRENT.json 的顺序。读者通过 pointer 解析活动 generation；新构建失败时 pointer 不切换，last-known-good 继续可读。系统不会提供“回滚到任意历史 generation”的用户命令。

现象先检查判定与处理

推理无响应API 健康、任务详情、模型快照大小、轮询错误瞬时错误让前端重连；404 会解锁。进程失败时保留任务 JSON/traceback 后重启。

布局溢出或乱码浏览器缩放、窄屏、UTF-8、U+FFFD保持 UTF-8，使用表格自身横向滚动；不要把页面级 overflow 当作解决方案。
上传失败后担心半发布错误响应、目录项与原文件摘要事务会恢复原 payload/catalog；修复验证错误再重传。它不是已成功上传后的历史回滚功能。

必须保留的安全边界

  • 路径：运行 ID 和发布资产必须是受限的单段/相对路径；拒绝绝对路径、./..、反斜杠、路径穿越、软链接/重解析点逃逸和 publication control 碰撞。
  • Windows 设备别名：CON、PRN、AUX、NUL、COM1–COM9、LPT1–LPT9 及带后缀变体不能作为发布路径组件。
  • 可信源码：算法/特征 .py 在 API 进程内执行；不要向不可信用户开放上传端点。
  • Pickle：上传和推理读取都会反序列化；只接受来源、摘要和依赖均已审查的模型。
  • 网络：API 当前返回宽松 CORS *，设计目标是绑定 127.0.0.1 的本机可信操作。不要未经认证直接暴露到共享网络。
