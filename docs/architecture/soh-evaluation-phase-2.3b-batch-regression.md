# SOH Evaluation 阶段 2.3B：批量回归、真实复测与跨页一致性

更新时间：2026-08-14

## 1. 阶段目标

阶段 2.3B 将单个固定 Cycle 的复测闭环升级为可审计的批量回归闭环，并统一所有页面使用的案例事实：

- 从当前固定样本扩展同一电芯的相邻 Cycle，默认范围为 `±2`，最多 5 条；
- 扩展时继续锁定数据集、候选、数据快照、协议划分和模型 artifact，不允许混入其他上下文；
- 使用不可变模型产物执行真实重新推理；没有可执行产物时只允许证据重放，不能关闭复测门禁；
- 基线与复测按同一回归集逐点比较，不再把局部复测指标与整案聚合指标直接相减；
- 将失败定位到数据集、资产、Cycle、协议、候选、模型产物和判据；
- 训练、推理、算法包、洞察、总览与评测页统一显示同一案例版本和状态。

## 2. 批量回归契约

现有接口保持不变：

`POST /api/v2/regression-sets/{regression_set_id}/members`

新增参数：

- `neighbor_radius`：整数，范围 `0..20`；
- `0` 表示仅加入当前固定 Cycle；
- `2` 表示加入当前 Cycle 及前后各 2 个 Cycle；
- 批量候选必须同时匹配当前问题单固定的 `dataset`、`asset_id`、`candidate_id`、`dataset_snapshot_id`、`split_assignment_id` 与 `model_artifact_id`。

服务端返回请求数量、新增数量、已存在数量和精确成员列表，并写入 `regression_set.members_added` 不可变工作流事件。重复提交使用数据库主键去重。

## 3. 复测差异契约

复测结果升级到 `schema_version: 1.1.0`，比较契约为：

`controlled-retest-comparison/1.0`

结果增加：

- `baseline_metrics`：同一批成员的冻结基线指标；
- `case_baseline_metrics`：问题创建时的整案判定指标，仅作上下文参考；
- `metric_deltas`：同一批成员复测值减基线值；
- `record_deltas`：逐样本预测、绝对误差、区间覆盖与 MAE 贡献差异；
- `regression_summary`：改善、持平、退化数量和最差样本；
- `failure_localization`：数据集、资产、协议、划分、候选、模型产物、失败判据和超限样本。

负的 MAE 差值代表改善，正值代表退化；PICP 则相反。误差绝对差在 `1e-12` 内记为持平。

## 4. 跨页面统一事实

前端新增统一的案例投影，所有主页面从同一服务端案例与复测工作区读取：

| 统一字段 | 展示位置 |
| --- | --- |
| 案例 ID / 版本 | 页头、评测上下文带 |
| 运行 ID / 执行状态 / 来源 | 页头运行元信息 |
| 数据集 / 数据快照 / 电芯 / Cycle | KPI、评测上下文带和证据区 |
| 候选 / 特征 / 模型 artifact | KPI、评测上下文带和判定检查器 |
| 协议划分 / 判据版本 | 评测上下文带 |
| 当前判定 / 问题数 / 批量复测样本数 | KPI 与闭环区 |

签名状态按案例版本判断：只有 `EvidencePack.case_version` 等于当前案例版本时才显示“已签署”。历史签名包继续保留，但不再冒充当前版本的发布状态。

训练页仍只承担数据、特征、算法、协议和种子的组合设计；Pickle 与 manifest 导入继续集中在算法包管理页。
