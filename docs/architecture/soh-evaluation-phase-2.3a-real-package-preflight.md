# SOH Evaluation 阶段 2.3A：真实预检、训练与不可变算法包

更新时间：2026-08-14

## 1. 阶段目标

阶段 2.3A 将“设计与训练”从组合选择界面升级为真实、可阻断、可复验的训练入口：

- 训练页只负责选择数据集、特征、算法、协议和随机种子；
- 外部 Pickle 与 manifest 只在“算法包管理”中导入；
- 每次启动前由后端基于真实数据执行权威预检；
- 训练结果按折次生成内容寻址的不可变模型包；
- 报告中的数据快照、预检、任务、折次和模型产物可以相互追溯。

## 2. 真实执行链路

1. 前端把当前组合提交到 `POST /api/training/preflight`。
2. 服务端规范化请求，读取 QC 后的真实数据，执行特征变换并检查协议分组数量。
3. 服务端为每个数据集计算内容摘要，返回 `dataset@sha256:*` 快照和确定性的 `preflight@sha256:*`。
4. 只有所有组合均为 `ready` 或 `warning` 时，运行按钮才启用；`blocked` 组合不能提交。
5. 创建任务时再次校验预检身份；真正执行前再计算一次，数据或选择发生变化即拒绝旧预检。
6. 每个成功折次生成一个模型包。包写入前完成 manifest 校验、可加载性检查和预测冒烟测试。
7. 模型字节与 manifest 分别计算 SHA-256；同名包更新前，旧版本原样归档到 `_artifacts/<sha256>/`。
8. `run_config.json`、`leaderboard.json` 和 `dataset_leaderboard.json` 写入任务、预检、数据快照与模型产物引用。

## 3. 关键契约

### 3.1 训练预检契约

- 版本：`training-preflight/1.0`
- 输入：数据集、算法、特征集、协议、随机种子
- 数据检查：真实 QC 样本数、特征列覆盖、空值后可用行数
- 协议检查：LOCO 至少两个电芯；LODO 至少两个数据集；LCHO 至少两个已知化学体系
- 输出：组合状态、阻断原因、样本数、数据快照、确定性预检 ID

### 3.2 模型包契约

- 版本：`1.0.0`
- 身份：`model@sha256:<model bytes digest>`
- 必需语义：算法、特征集、训练数据、特征列、目标列、预测接口、协议、留出对象和随机种子
- 完整性：`manifest_sha256` 与 `model_sha256`
- 可执行性：反序列化成功且 `predict(...)` 冒烟测试通过
- 历史兼容：旧案例继续按完整 artifact ID 精确加载，不跟随同名资源漂移

## 4. 前端职责调整

- “设计与训练”突出特征 × 算法组合，删除手工上传模型的主流程依赖。
- 组合矩阵直接展示后端的“可运行 / 有提示 / 已阻断”结果和原因。
- 运行区展示真实 QC 样本数、预检摘要和固定的数据快照。
- 成功后展示聚合 MAE、折次数和不可变模型产物数。
- “算法包管理”集中处理 Pickle + manifest 导入、契约版本与内容摘要；有推理结果的包优先，其次展示版本化可复验包。

## 7. 阶段 2.3B 建议边界

下一阶段应聚焦批量回归与复测闭环：将失败门槛定位到数据集、折次、指标和模型 artifact，展示前后两次运行的贡献差异，并将复测证据回写当前案例。该工作不应重新把文件上传或人工组装模型包带回训练页。
