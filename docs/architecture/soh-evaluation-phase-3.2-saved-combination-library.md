# 阶段 3.2：完成组合库与泛化验证

## 结论

阶段 3.2 已把训练完成结果、推理完成结果和第三页证据画布收敛为同一条可追溯链路。用户可在任务完成后选择是否将结果加入“已完成组合”；取消收藏只影响快捷列表，不删除任务、模型产物、预测记录或审计事件。第三页按不可变模型产物聚合训练内评估、同源回放和跨数据集验证，避免把三个语义不同的结果复制成互不关联的列表。

## 产品语义

训练列表和推理列表共享模型身份，但不使用同一条结果记录：

| 结果类型 | 固定内容 | 第三页用途 |
| --- | --- | --- |
| 训练内评估 | 训练任务、模型 artifact、训练数据快照、特征方案、协议和聚合指标 | 比较训练稳定性；不绘制逐 Cycle 轨迹 |
| 同源回放 | 同一模型 artifact、训练数据集上的推理任务、PredictionRecord 与原始曲线 | 检查可重放性和训练/推理差异 |
| 跨数据集验证 | 同一模型 artifact、新目标数据集快照、推理任务和证据 | 累积模型泛化画像 |

因此，训练和推理不是两套独立组合库，也不是完全相同的一张结果表。它们以 `model_artifact_id` 作为父级身份，以训练或推理运行作为子结果。未完成训练的组合不能收藏；未完成推理的模型—目标数据集组合不能在第三页显示真实轨迹。

## 数据与接口

- 案例 schema 升级到 `1.2.0`，新增 `saved_combinations` 与 `active_saved_combination_id`。
- 保存记录由服务端从真实训练/推理产物生成，前端不能自行伪造指标、判定或证据引用。
- 保存、移除和激活均写入案例事件流；移除收藏不会删除运行历史。
- 新增接口：
  - `POST /api/v2/cases/{case_id}/saved-combinations`
  - `POST /api/v2/cases/{case_id}/saved-combinations/activate`
- 激活训练结果时，第三页只显示训练聚合摘要和“进入推理验证”；激活推理结果时恢复该结果的候选、数据集、PredictionRecord、轨迹、原始信号和特征曲线。

## 界面收敛

- 第一页只保留一个主流程动作，并在运行计划旁提供“加入已完成组合”开关。
- 第二页继续以多目标数据集泛化验证为中心，保存开关不与“进入评测与证据”竞争主操作。
- 第三页顶部使用紧凑横向结果条，按模型 artifact 分组显示训练内评估、同源回放和跨数据集验证。
- Cycle 输入、中央原始/特征曲线和右侧 PredictionRecord 血缘使用同一当前画布记录；尚未固定的 Cycle 明确显示“待固定”。
- 训练结果不生成伪 SOH 轨迹；只有完成推理并产生真实 PredictionRecord 后才显示逐点和曲线证据。
