# SOH Evaluation 阶段 2.4：案例流水线与候选产物收敛

更新时间：2026-08-14

## 1. 阶段目标

阶段 2.4 将“设计与训练 → 推理验证 → 评测与证据”收敛为同一个案例对象，解决折次模型过多、页面之间需要重复选择、刷新后上下文丢失的问题。

- 训练成功后按“算法 × 特征 × 协议”聚合折次产物；
- 每组默认只推荐一个候选模型，完整模型库收进高级区；
- 推理继承当前训练任务、候选模型和兼容数据集；
- 推理完成后自动绑定代表预测记录和原始曲线；
- 同一个案例持续记录训练任务、推理任务、证据、复测、对账、评审和 EvidencePack；
- 提供一条可重复执行的真实闭环验收命令。

## 2. 界面和交互契约

### 2.1 训练产物不是 32 个并列按钮

一个 LOCO 训练任务可能生成多个折次模型。推理页默认展示候选组，不再把每个折次当作一项主要选择：

- 候选组：算法、特征集、协议、折次数；
- 推荐产物：优先沿用已执行的推理模型，否则使用训练摘要中的最佳折次；
- 进入推理时每组只选择一个推荐产物；
- 其他历史模型和不兼容组合位于默认折叠的“高级：改选其他算法包”。

完整训练任务通过任务 ID 重新读取，因此页面刷新后仍能恢复 `saved_models`、`model_artifacts` 和推荐折次，不依赖精简任务目录。

### 2.2 页面共享同一个案例身份

三个主阶段共享 `EvaluationCase`：

1. 设计与训练：写入 `training_job_id` 和不可变候选产物；
2. 推理验证：写入 `inference_job_id`，继承推荐模型和兼容数据集；
3. 评测与证据：写入代表预测记录、证据完整性、门槛判定、复测、对账、评审和 EvidencePack。

案例与任务身份保存在服务端；刷新、切换阶段或直接打开审计地址时，仍恢复同一案例。

### 2.3 自动选择代表证据

推理页只需提交“候选模型 + 数据集”。若未指定电芯或 Cycle，服务端会：

1. 按数据集、候选 ID 和不可变模型 artifact 过滤预测记录；
2. 优先选择绝对误差最高的高信息量记录；
3. 自动回填电芯、Cycle、sample ID；
4. 继续派生数据快照、切分协议、预测记录和原始曲线覆盖状态。

用户仍可在证据画布中改选其他 Cycle，但不再需要先完成多层手工选择才能进入评测。

## 3. 一键真实验收

在仓库根目录执行：

```powershell
$env:PYTHONPATH='D:\SOH_eval\src'
$env:PYTHONUTF8='1'
python scripts/run_phase24_pipeline_acceptance.py
```

每次未指定 `--profile` 时生成新的 profile；也可传入固定名称便于审计。流水线会执行真实预检、真实训练、真实推理、证据发布、模型重新推理复测、问题关闭、KPI 对账、评审和 EvidencePack 签署。若任何一步失败，命令返回失败，不生成“成功”摘要。
