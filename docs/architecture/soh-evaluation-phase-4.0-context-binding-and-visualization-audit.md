# 阶段 4.0：案例上下文绑定与旧可视化迁移审计

日期：2026-08-17

## 结论

- 三个流程页现在以服务端 `EvaluationCase.context_binding` 为唯一语义上下文，不再依赖浏览器会话缓存或按模型名/特征名猜测结果。
- `D:\battery_SOH` 的 SOH 主看板数据与主要绘图能力已经迁入。ESS detection 被正式定义为非迁移范围：本项目不导入其数据、摘要、曲线或交互入口，旧目录保持原样。

## 上下文一致性保护

### 统一绑定对象

案例文档 schema 升级为 `1.3.0`，每个版本包含由服务端计算的 SHA-256 绑定：

- 案例、流程阶段与绑定代际；
- 训练任务、推理任务和运行 ID；
- 已保存组合和当前候选；
- 模型、特征方案与模型产物摘要；
- 训练数据集、目标数据集、当前证据数据集与数据快照；
- 协议与证据选择。

浏览器只携带绑定 ID，不能提交新的候选或产物身份来改写服务端结果。

### 强制规则

1. 训练、推理启动必须提交当前案例 ID 和绑定 ID。
2. 任务只能回写创建它的案例；同案例的旧代际任务也不能覆盖当前任务。
3. 证据画布、轨迹、逐点记录、原始曲线和评审工作区均校验绑定 ID。
4. 新训练代际在同一案例事务中清空旧推理、旧候选、旧证据选择、旧判定和旧评审结果。
5. 新推理代际清空旧证据选择、旧判定和旧评审结果。
6. 已完成组合只能由服务端读取成功任务产物后保存；无法保存浏览器伪造或未完成任务。
7. 切换已完成组合时恢复精确的任务、模型产物、特征、目标数据集和证据身份，不做名称近似匹配。
8. 上下文冲突返回 HTTP 409；前端重新读取当前案例后再渲染，不继续使用旧响应。
9. 推理任务在创建时持久化 `模型名 → model@sha256` 的不可变绑定；执行时按摘要加载产物归档，不再按当前模型目录中的同名项加载。
10. 旧推理任务从各自运行目录中的 `model_catalog.json` 快照升级到 inference-job `1.1.0` 并原子回写；快照缺失时标记为不可核验，不使用实时模型目录猜测。

### 真实回归结果

案例 `EV-20260817-89CA6203` 的历史推理任务原先只记录模型名称；同名模型后续更新后，第 2 页会解析到新摘要，导致第 3 页误报不一致。迁移后，该任务恢复出 4 个原始模型绑定，其中当前候选固定为 `model@sha256:25218a9f...3120bc`。真实浏览器逐页加载后显示：设计与训练一致、推理验证一致、评测与证据一致。

## `D:\battery_SOH` 可视化迁移清单

### 已完成

| 能力 | 迁移状态 | 当前承载位置 |
|---|---|---|
| 9 个 SOH 场景（XJTU、MIT、NASA、CALCE、Oxford、HUST、SNL、UConn、RWTH） | 完成 | `frontend/app/battery-dashboard` |
| 场景数据、SOH 轨迹和 V/I/T/IC 曲线文件 | 完成 | 20 个 JSON 文件，和源文件 SHA-256 一致 |
| SOH 真值/预测/95% 区间 | 完成 | 原生看板和第 3 页证据画布 |
| Cycle 下钻、V/I/T、IC、特征窗高亮 | 完成 | 第 3 页由 PredictionRecord 和 CurveSegmentRef 驱动 |
| 场景指标、算法参数、特征信息、全体电池 3σ、RWTH 时间轴/物理仿真 | 完成（原生看板） | 本地原生 SOH 看板 |

原生 SOH 包的同步清单明确记录 `scenario_count=9`、`include_soh_curves=true`。源目录中的 SOH 同名 JSON 与项目副本的 SHA-256 全部相同。

### 明确不迁移

| 能力 | 当前状态 | 产品边界 |
|---|---|---|
| ESS detection 数据、摘要与降采样预览 | 明确排除 | 不进入 profile、辅助页或独立 HTML |
| ESS 舰队一致性热力图 | 明确排除 | 保留在旧项目，不在新工作台重建 |
| ESS 异常单体曲线、事件表、工况画像 | 明确排除 | 保留在旧项目，不进入第 3 页证据语义 |
| ESS 原始完整曲线进入原生包 | 明确排除 | `ess_detection.json`、`ess_detection_curves.json` 不在 `battery-dashboard/data` |
| 旧看板所有视图直接嵌入第 3 页 | 非目标 | 第 3 页只展示与当前不可变 PredictionRecord 同源的审计证据 |

源目录中的以下两个文件不属于迁移清单：

- `ess_detection.json`
- `ess_detection_curves.json`

这不是迁移缺口，而是正式产品边界。导入器、原生同步、前端加载和交付检查均强制执行 `scope.ess_detection=false`；不存在通过参数重新开启的路径。

## 后续边界

保持第 3 页为 SOH 证据评审，不把 ESS 无监督异常语义混入 SOH 判据。后续数据同步、辅助页扩展、独立 HTML 与发布包均只覆盖 SOH；除非重新批准产品范围，不新增 ESS detection 入口。
