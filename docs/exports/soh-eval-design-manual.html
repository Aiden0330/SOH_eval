一、项目定位与整合范围

本项目不是单一模型脚本，而是围绕锂电池 SOH 估计建立的评测工作台。它把 D:\battery_SOH 作为数据、曲线、算法设计和原生看板资产来源，把 D:\SOH_eval 作为统一测评入口、前后端系统、模型资产库和离线交付层。

数据湖
多源

测评工作台
闭环

统一算法接口、数据选择、训练任务、Pickle 模型推理、排行榜和诊断。

交付形态
离线

支持同步原生看板资产、生成目录包和单 HTML 展示包，便于迁移演示。

核心边界：训练页签面向“生成模型与公平训练评测”，推理页签面向“已有 Pickle 模型在新数据集上的迁移泛化与速度测评”。这一区分让模型开发、模型资产复用和线上推理能力验证互不混淆。

测评协议

LOCO 留电池测评，考察同一数据集内未见电芯泛化能力。

LODO 留数据集测评，考察跨数据集迁移能力，是算法公平对比的关键协议。

LCHO 留化学体系测评，考察跨材料体系泛化能力，适合多化学体系扩展后启用。

三类协议都禁止把同一电芯的循环随机切到训练与测试两侧，否则会把时间相关性误当成泛化能力。

原生 SOH 看板场景

battery_SOH 的完整看板提供 XJTU、MIT、NASA、CALCE、Oxford、HUST、SNL-LFP、UConn 等实验室场景，以及 RWTH 户储现场场景。它强调 SOH 轨迹、95% 区间、误差分布、特征窗、原始曲线和场景门控，是 SOH_eval 中“完整 SOH 看板”页签的主要内容来源。

四、算法原理介绍

本项目的算法设计遵循“可部署特征、严格切分、点估计与不确定度并行验收”的原则。重点不是只追求单次最低误差，而是确保模型在跨电芯、跨数据集和跨场景迁移时仍能解释失败、量化风险并复现实验。

算法流程图：从特征帧进入模型之前，先由切分纪律和特征准入控制泄漏；输出端同时验收精度、不确定度与物理一致性。

SOH 与标签

SOH 表示电芯健康状态，计算方式为 SOH = capacity_Ah / C_rated。 C_rated 来自数据集元信息，不在代码中硬编码。标签清洗会剔除明显容量尖刺和非物理值，避免模型学习由部分充放电、标定异常或记录错误导致的噪声。

特征工程

特征族核心特征物理含义准入原则
充电电压窗q_win_ah、t_win_s指定电压窗内的充入容量和充电时长，直接反映容量退化。只使用测试时可获得的当前循环信息。
IC 曲线ic_peak_ah_per_v、ic_peak_voltage_v增量容量曲线峰高与峰位，反映相变平台与极化漂移。对电压排序、插值、平滑，并剔除边界假峰。
操作统计电压、电流、温度、时间、容量统计特征。对不同采样频率和循环长度形成稳健摘要。归一化只在训练集拟合，避免测试域信息泄漏。
禁止项DCIR、RPT 脉冲、cycle_fraction内阻脉冲并非所有部署场景可得；全寿命归一化依赖未来信息。即使文献中强相关，也不能进入默认公平测评。

点估计模型

battery_SOH 的主模型族为 TabularSOHEnsemble，由 Ridge、HistGradientBoosting 和 RandomForest 三个分支组成。Ridge 提供线性外推主干，HistGBDT 捕捉非线性退化，RandomForest 抑制方差。SOH_eval 当前训练测评还包含 GBDT 等插件算法，并支持用户上传新的可信本机算法。

Ridge

简单、稳定、推理快，适合作为线性基线与速度参考。

HistGBDT

对表格特征强，能处理非线性退化，是当前推荐默认算法的重要候选。

RandomForest

通过树集成降低方差，对异常点和局部非线性更稳健。

不确定度、后处理与门控

SOH 输出必须包含 95% 区间。系统支持 split conformal、CQR、组条件化共形和自校准半宽等策略。评估时不只看覆盖率，还要同时看区间宽度：单纯拉宽区间可以提高覆盖率，但会失去工程价值。

后处理采用“等渗非增地板 + 有界回升”。锂电池容量总体随循环下降，但静置恢复和测量噪声会出现小幅回升；算法允许受控回升，同时防止预测曲线出现非物理振荡。

门控目的典型指标
精度门控判断模型是否能满足场景误差要求。MAE、RMSE、MAPE、EOL 区域误差。
校准门控判断区间是否既覆盖真实值又不过宽。PICP、平均区间宽度、alpha accuracy。
物理一致性判断 SOH 范围与退化趋势是否可信。单调性违例率、范围违例率、最大回升。

典型操作流程

准备数据
将公开数据集或自有数据放入数据目录，处理为统一特征帧。前端目录刷新后即可勾选。
接入算法或特征
训练页签可上传可信本机算法插件或特征方案；推理页签优先上传已训练好的 Pickle 模型。
配置测评
选择数据集、算法、特征、协议和种子。公平比较必须保证同一数据范围、同一协议和同一指标口径。
启动任务并查看状态
训练任务时间较长属于正常现象，因为它包含 fit、predict、区间和指标计算；推理任务只加载模型并预测，通常更快。
进入结果与看板
排行榜用于算法比较，完整 SOH 看板用于解释某个场景或电芯的轨迹、区间、误差和原始曲线。
同步与打包
完成测评后生成离线包，交付给没有本地原始数据的机器进行浏览和汇报。

六、完整 SOH 看板与测评页签的关联

训练和推理页签回答“哪种算法在给定数据范围上更好”；完整 SOH 看板回答“为什么这个结果可信或失败”。二者通过数据集、模型、特征集、协议和 held-out key 关联：排行榜给出指标，完整看板给出轨迹、曲线和逐点证据。

排行榜视角

当前主线训练比较中，GBDT 与 TabularSOHEnsemble 在 battery_soh_operational 特征集和 LOCO 协议下形成基准对照。推理测评记录显示，已有模型可在多个目标数据集上完成迁移测速，最快记录约为每千样本 13ms 量级。

轨迹视角

原生看板提供真值、预测、95% 区间、误差分布、V/I/T 原始曲线和 IC 曲线。它让用户能从“一个 MAE 数字”下钻到“某个循环点的特征窗与曲线形态”。

SOH 看板用于解释排行榜：点选某条预测轨迹上的循环点，即可查看对应曲线和特征窗。

七、文献综述与方法定位

本项目的方法路线属于“多数据集 SOH 评估 + 传统表格模型/深度模型基线 + 共形不确定度 + 可解释曲线下钻”。与多数公开 benchmark 相比，差异点在于训练/推理分离、模型资产持久化、区间门控、物理一致性和离线交付。

研究脉络

早期循环特征与曲线特征

代表性工作使用早期循环电压或容量曲线预测寿命，证明曲线形态在容量明显下降前已经包含退化信息。本项目借鉴这一思想，但任务从寿命预测转为逐循环 SOH 估计，并强调部署可得的充电侧特征。

多数据集 Benchmark

BatteryML 和 SOHbenchmark 提供了公开数据集整合与多模型对照。本项目吸收它们的基线矩阵思想，同时加入数据泄漏约束、区间输出和门控。

物理约束与 PINN

PINN4SOH 等工作把退化机理融入神经网络。本项目目前以物理一致性门控和后处理实现工程约束，后续可将物理模型作为候选算法插件接入。

不确定度与共形预测

共形预测为区间覆盖提供有限样本保证，CQR 进一步让区间随样本难度变化。本项目把覆盖率和区间宽度作为并列验收对象。

当前设计取舍

问题设计选择原因
训练和推理是否区分？强制区分。训练评测包含 fit、区间和指标计算；推理评测只加载模型预测，更适合验证模型资产迁移和线上速度。
上传新模型应传源码还是 Pickle？训练页传源码插件；推理页传 Pickle 模型。源码用于产出新模型，Pickle 用于复用已有模型并验证泛化。
是否复制 battery_SOH 原始数据？按受控子集迁入项目：正式数据集保留原始证据与曲线，其余大型或未接入数据不复制。兼顾项目自包含、可解释展示与磁盘占用；迁移范围以 data/manifest.json 为准。
是否保留异常检测页签？从 SOH 主工作台移除。异常检测语义与 SOH 估计门控不一致，容易造成评测目标混淆。
是否用单一排行榜说明优劣？排行榜 + 场景看板 + 失败组合共同解释。算法优劣依赖数据范围、协议、速度、区间质量和物理一致性。

建议路线

补齐全量公平矩阵
以七数据集为默认范围，完成 LOCO、LODO 与关键算法组合的可复现实验，避免局部结果误导推荐。
加强模型兼容性检查
推理页在启动前明确显示模型所需特征列、目标数据集缺失列、可自动填补列和不可运行原因。
把完整看板与排行榜深链接
从排行榜某一 held-out key 直接跳转到对应电芯轨迹、误差和曲线下钻。
沉淀报告模板
将训练、推理、数据同步和打包任务自动生成验收报告，便于评审与交付。
扩展算法生态
新增深度序列模型、物理约束模型、分位回归模型和轻量在线推理模型，但统一进入相同测评契约。
