Executive decision

先给结论：保留三步主线，辅助能力降级

当前功能已经能贯通真实案例，但导航仍把“完成任务”和“管理工具”放在同一层，增加理解成本，也诱发无关数据预加载。

00

建议从 6 个可见入口收敛为 3 + 1

始终展示三个主流程；只保留一个“工具”入口。“洞察建议”不再单列页面，而是回到用户做决定的训练、推理和评测上下文中。

保留设计与训练、推理验证、评测与证据——它们构成同一 Evaluation Case 的连续状态。
下沉算法包管理、可信总览进入“工具”抽屉，并按角色显示；普通评测人员无需频繁进入。
合并洞察建议分别嵌入训练组合推荐、推理迁移建议和评测失败解释，不再成为重复结果页。

简化不等于删除可信控制

摘要、证据血缘、判据和审计轨迹必须保留；简化方式是“默认只显示当前决策所需内容”，把完整细节放入可展开区或抽屉，而不是绕过门禁。

Panel handbook

六个面板的功能与使用说明

以下说明按当前真实界面命名。工具栏可筛选主流程或辅助入口。

03
01

设计与训练

核心阶段 · 把“想比较什么”变成可复现训练任务

✓ 保留并精简

功能

在统一数据与协议下，组合特征方案和算法候选，进行权威预检后启动训练。训练成功的模型包自动进入算法包管理，不需要在此手工上传 Pickle。

主要输入数据范围、特征方案、算法、LOCO/LODO/LCHO、seed
主要输出RunSpec、训练任务、候选模型包、案例上下文
推荐操作顺序
  1. 确认数据源与案例。 顶部“数据源”是发布的资料快照，不等于本页的数据集勾选；先确认正在使用正确 Profile。
  2. 选择数据范围。 同一轮比较只放入可按相同协议解释的数据集；不要把训练域和目标 held-out 域混为一个含义。
  3. 先选特征，再选算法。 先看特征列覆盖和可解释性，再选基线与候选算法，界面会形成特征 × 算法组合。
  4. 确认协议与 seed。 日常快速比较可用 LOCO + seed 0；正式稳定性评测再展开多协议、多 seed。
  5. 查看预检与组合数。 只提交 ready / warning 组合；blocked 代表 schema、资源或可信执行条件不足。
  6. 点击“运行所选组合”。 等待任务成功后，主按钮应转为“进入推理验证”，继续沿用同一案例。
当前子面板分别做什么
区域功能操作要点
数据范围决定本轮组合在哪些数据上训练/比较优先选择 QC 通过、schema 明确的数据
组合特征与算法生成公平比较矩阵组合过多时先缩小特征，再扩算法；避免无意义笛卡尔积
组合预览 / Run plan显示预计任务数和预检状态确认没有重复组合、缺列或不可执行项
验证协议与 seed定义泛化口径与重复性协议含义要与最终结论一致
训练产物显示任务、候选与包登记状态只作为结果摘要；资产管理去“算法包管理”
适合在此完成

选择特征和算法组合、查看兼容性、启动训练、跟踪训练产物。

不应放在此处

上传外部 Pickle、管理 manifest、手工打包离线文件——这些属于资产或系统工具。

→

进一步简化

默认显示“推荐组合 + 一个主按钮”；协议、多 seed、超参数和批量展开收进“高级设置”。只渲染可兼容组合，并用组合指纹去重，避免用户提交同一 dataset snapshot × feature × algorithm × protocol × seed。

02

推理验证

核心阶段 · 检查训练候选能否在目标数据上正确、稳定、快速地运行

✓ 保留并自动继承

功能

默认继承本案例的训练候选，选择目标数据集后执行 inference-only 测评，给出迁移误差、速度/吞吐、特征兼容性和风险解释。它不是第二个训练页。

主要输入已校验模型包、目标数据集、运行策略
主要输出预测记录、迁移指标、曲线引用、评测候选
推荐操作顺序
  1. 确认“本次训练候选”。 正常情况下无需重新选模型；只有复验历史包时才展开“高级：改选其他算法包”。
  2. 选择目标数据集。 目标集应与训练域的角色清楚区分，且具备模型所需 feature schema。
  3. 阅读兼容性结论。 ready 可直接运行，warning 需理解风险，blocked 不应通过换按钮绕过。
  4. 选择运行策略。 默认“仅运行兼容组合”；“包含风险组合”只用于受控诊断，并保留原因。
  5. 点击“启动推理测评”。 完成后查看迁移 MAE、吞吐和失败组合，并进入同一案例的评测与证据。
结果如何解读
结果回答的问题不能单独推出什么
迁移 MAE模型在目标域上的点预测误差不能替代区间校准、切片最坏值和物理一致性
推理速度 / 吞吐已固定模型的 inference-only 工程表现不能与包含训练耗时的全局任务时间直接比较
兼容性模型所需列、schema、运行环境是否匹配兼容不代表精度一定达标
预测记录后续证据画布的 record_id 与曲线入口未绑定记录时不能生成可信原始曲线
默认路径

继承训练候选 → 选目标集 → 仅运行兼容组合 → 进入评测与证据。

常见误区

在 1,000+ 包中重新寻找刚训练的模型，或把训练 CV 最优直接当作迁移最优。

→

进一步简化

把兼容性从常驻大面板改为顶部状态条：无风险时只显示“全部兼容”；有问题时才展开详情。高级模型库保持折叠并改为服务端搜索/分页，成功后主按钮原位变为“进入评测与证据”。

03

评测与证据

核心阶段 · 从聚合结论连续下钻到电芯、Cycle、原始曲线和审计闭环

✓ 核心证据页

功能

用三栏工作区把“比较谁”“证据是什么”“为什么通过/阻断”放在同一屏。SOH 轨迹与原始 V/I/T/IC/DV 使用同一个 candidate + dataset + asset + cycle + record_id。

主要输入案例、候选、证据数据集、电芯、Cycle、判据
主要输出判定、证据覆盖、问题/复测、审计轨迹、EvidencePack
推荐操作顺序
  1. 先看上下文带。 确认三页组合一致：案例、数据集、算法、特征、协议/判据必须匹配。
  2. 在左栏确定比较范围。 选择判据集、候选算法、证据数据集和代表电芯；一次选择会同步驱动中栏与右栏。
  3. 从轨迹选择 Cycle。 点击 SOH 轨迹点，或在 Cycle 数字输入框输入有效编号并按 Enter；“等待选择 Cycle”消失后才有逐点记录。
  4. 切到“原始 V / I / T / IC / DV”。 读取同一 record_id 的测量/派生曲线；IC/DV 如由实测信号派生，来源应明确标注。
  5. 阅读右侧判定检查器。 先处理 blocker，再查看指标贡献、证据完整度、血缘和不可变事件。
  6. 需要时建立闭环。 固定当前 Cycle → 加入回归集 → 同协议复测/证据重放 → 自动回填；证据完整后再提交评审。
三栏与页签说明
区域功能使用原则
左：比较范围判据、候选、数据集、电芯它定义当前证据视图，不应在中栏再放一套重复筛选器
中：SOH 轨迹真值、预测、区间、异常点和 Cycle 选择用轨迹找异常点；统计指标仍基于全量，不用视觉降采样值重算
中：原始曲线V/I/T、IC/DV、特征窗和采样摘要只有选中有效 Cycle/record 后按需加载；失败需显示真实原因
中：逐 Cycle 闭环固定样本、问题、回归与复测只有发现问题时展开；不可覆盖已签署案例
右：判定检查器结论、阈值、覆盖、血缘、评审和 EvidencePack默认优先显示 blocker；完整事件轨迹按需展开
曲线可用的前提

推理成功且 prediction record、CurveSegmentRef 与数据摘要已经绑定，随后选中有效 Cycle。

遇到 HTTP 404

通常代表当前记录没有对应曲线、曲线键不匹配或源摘要变化；应追查绑定，不生成演示曲线冒充证据。

→

进一步简化

保留三栏，但让右栏默认只显示“结论 + blocker + 覆盖度”，血缘、审计轨迹和复测表单折叠；逐 Cycle 闭环仅在选点或失败判据后出现。Cycle 选择固定在证据页签右上角，轨迹和原始曲线共用，避免用户找不到入口。

A1

算法包管理

辅助入口 · 外部模型与可信插件的唯一接入、校验和追踪位置

↓ 下沉到工具

功能

集中导入 Pickle + manifest，查看训练自动登记的算法包，并核对内容摘要、特征 schema、来源和可信执行边界。普通训练不需要手工上传。

主要输入可信 Pickle、JSON manifest；高级插件或数据文件
主要输出已注册模型资产、不可变摘要、兼容性状态
推荐操作顺序
  1. 优先使用训练自动产物。 只有导入外部既有模型时，才选择 Pickle 和对应 manifest。
  2. 核对来源。 Pickle 反序列化可执行代码，只允许可信本机模式和可信来源。
  3. 点击“导入并校验”。 系统应同时验证内容摘要、manifest 版本、算法类型和 feature schema。
  4. 查看已注册算法包。 通过摘要、训练数据、特征列和最近推理指标定位资产，而不是只看文件名。
  5. 高级接入按需展开。 Python 算法插件、特征插件、数据集和 battery_SOH 根目录属于管理员操作。
当前子面板分别做什么
区域功能主要风险
导入算法包Pickle + manifest 成对接入来源不可信、manifest 与二进制不一致
高级接入源码算法、特征插件、数据和 battery_SOH执行任意代码、插件契约漂移
已注册算法包展示训练产物与外部包的统一资产表列表过大、名称相似导致选错版本
包校验摘要、契约与执行边界只显示“已导入”但未确认可复验
→

进一步简化

导航中下沉为“工具 → 算法资产”。把四类导入动作统一成一个“导入资产”向导，默认类型为 Pickle 包；高级类型按角色解锁。模型表改为服务端分页/搜索和详情抽屉，首屏只取摘要与前 30–50 条。

A2

可信总览

辅助入口 · 跨案例查看数据质量、稳定性、校准与交付状态

↓ 拆分并下沉

功能

当前页面同时承载 battery_SOH 诊断、数据同步、离线打包、交付验收、数据范围、多 seed 稳定性、特征 × 算法矩阵、排行榜、PICP 和 QC。它是信息最多、职责也最混杂的入口。

主要输入全局结果、QC、诊断资产、打包目录
主要输出跨案例诊断、质量风险、离线交付物与验收结果
推荐操作顺序
  1. 先确定目的。 若要看当前案例结论，应返回“评测与证据”；本页适合看全局质量和跨组合趋势。
  2. 先看 QC 与数据范围。 质量门控不通过时，不继续解释排行榜或 PICP。
  3. 再看稳定性和矩阵。 多 seed 波动、跨域 MAE 和校准性用于找稳健候选，不替代当前案例判据。
  4. 交付操作谨慎执行。 同步、目录包、单 HTML 和验收属于管理员/发布工作，不应成为日常评测步骤。
现有内容如何重新归类
现有内容建议归属默认可见性
QC、数据范围、稳定性、矩阵、PICP保留在“诊断总览”只展示摘要，点击下钻
battery_SOH 诊断摘要诊断总览的一个数据源卡对应 Profile 时显示
排行榜、算法优劣与洞察合并；在训练/推理中显示上下文版本总览仅保留跨案例入口
数据同步、目录包、单 HTML工具 → 交付与维护仅管理员角色
交付包验收报告发布动作完成后的自动结果无需独立“刷新验收”主按钮
→

进一步简化

把页面拆成“只读诊断”和“交付工具”两个标签，但都留在一个工具入口。诊断首屏只保留 4 个状态卡：数据 QC、泛化稳定性、校准性、物理一致性；重图表进入详情后再加载。同步 → 打包 → 验收合并为一个“生成交付包”流程，自动执行依赖步骤。

A3

洞察建议

辅助入口 · 把 LOCO/LODO、精度和速度结果转成场景化建议

↔ 合并到主流程

功能

汇总迁移推理 MAE、跨电芯泛化、训练稳定性和速度权衡，解释“推荐哪个算法以及为什么”。推荐是决策辅助，不是自动评审结论。

主要输入LOCO/LODO 结果、速度、校准与当前场景
主要输出推荐候选、理由、边界和替代方案
推荐如何使用
  1. 先选场景。 新数据集迁移优先看迁移 MAE；低延迟部署同时看 inference-only 速度；严谨评审还要看校准与物理一致性。
  2. 看推荐理由和边界。 训练 CV 最优不自动等于迁移最优，速度最快也不代表证据最完整。
  3. 回到对应主流程执行。 在训练页选择推荐组合，在推理页验证目标域，在评测页查看真实证据。
应保留的能力

场景化推荐、权衡解释、推荐依据与可追溯的结果链接。

不应保留的形态

与训练/推理结果重复的独立大页面，以及没有当前案例上下文的“全局最佳”。

→

进一步简化

移除顶层入口：训练页显示“推荐特征 × 算法”，推理页显示“迁移优先 / 速度优先”两种建议，评测页只在失败判据旁显示“下一步建议”。完整依据放入“为什么”抽屉，并链接回原始结果，不重复计算和渲染整页。

Operator FAQ

常见问题与快速判断

07
为什么训练页不能手工上传 Pickle？

这是刻意的职责分离。训练页只负责选择特征 × 算法组合；外部 Pickle 和 manifest 只能在“算法包管理”导入。训练成功的产物会自动登记。

为什么推理页看不到刚修改的算法或特征？

先确认训练任务已成功、产物已绑定到当前 Case，且推理页继承的是同一案例。若修改导致新的 feature schema，应先完成权威预检和新模型包登记。

为什么评测页显示“等待选择 Cycle”？

先在左栏选定证据数据集和代表电芯，再点击 SOH 轨迹点；也可以在页签右侧的数字输入框填写有效 Cycle 并按 Enter。没有有效 prediction record 时，Cycle 选择也不能产生曲线。

为什么轨迹或原始 V/I/T/IC/DV 显示 404？

常见原因是当前 prediction record 没有 CurveSegmentRef、曲线键不匹配、源文件摘要变化，或所选 Cycle 不在数据中。应在证据链中修复引用，不自动切到其他 Cycle，也不生成 Mock 曲线。

“可信总览”里的排行榜能直接决定发布吗？

不能。排行榜是跨组合诊断；正式结论还需要当前案例的协议、切片、区间校准、物理一致性、证据覆盖和人工评审。

推荐算法是否一定是最终候选？

不一定。推荐只是基于当前场景和已记录指标的决策辅助。迁移优先、速度优先、校准优先可能得到不同候选，最终要回到同一案例证据中判断。
