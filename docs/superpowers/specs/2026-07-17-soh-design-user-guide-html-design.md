# SOH 设计与工具使用说明书 HTML 设计

## 1. 文档状态

本规格已经用户批准。

最终交付物为：

`docs/soh-evaluation-system-design-and-user-guide.html`

最终 HTML 不显示版本号或日期。规格文件使用日期命名仅用于工程追踪。

## 2. 目标

生成一份面向管理者、研发人员和工具使用者的综合交付说明书，统一解释：

- 项目目标、能力边界和验收价值。
- Verification Fabric 的可信测评架构和证据链。
- Battery SOH 数据、特征、算法和曲线诊断能力。
- 当前前端五个页签及其职责。
- 数据集、算法、特征和 Pickle 模型的接入方法。
- 训练测评、冻结推理、结果发布和离线打包流程。
- 结果、排行榜、质量报告和 EvidencePack 的正确解读方式。
- 常见失败、安全边界和故障排查流程。

## 3. 非目标

- 不把目标架构或后续阶段写成当前已经上线的功能。
- 不复制旧手册中的历史任务状态、长跑进度、版本号或日期。
- 不依赖 CDN、在线字体、外部脚本或远程图片。
- 不把说明书做成新的测评前端或可提交任务的控制台。
- 不在文档中嵌入真实敏感数据、Pickle 内容或可执行插件源码。

## 4. 受众与阅读路径

### 4.1 管理者

推荐路径：

项目概览 → 核心能力 → 可信测评架构 → 风险与治理 → 验收结论

### 4.2 研发人员

推荐路径：

总体架构 → 核心契约 → 数据与算法边界 → 插件扩展 → 测试与证据治理

### 4.3 工具使用者

推荐路径：

快速启动 → 五页签说明 → 资源上传 → 训练/推理 → 结果解释 → 排障与打包

阅读路径只改变导航高亮，不隐藏正文，保证任何模式下内容完整。

## 5. 真实性边界

内容状态统一使用以下标识：

- `当前已实现`：以
  `codex/verification-fabric-phase0` 最新代码、测试、API 路由和前端为准。
- `已接入领域能力`：来自 `D:\battery_SOH` 的 SOH 算法、特征、曲线和完整看板能力，并说明其与测评主流程的关联边界。
- `目标架构`：Worker 隔离、前端 V2 和外部插件治理等后续能力，明确标为规划。

内容取证优先级：

1. 当前代码、测试和运行契约。
2. Verification Fabric 设计规格与 Phase 0 计划。
3. 实际数据目录、前端数据产物和 API 路由。
4. `D:\battery_SOH` 的系统、算法和研究文档。
5. 旧版使用说明，仅作为待核对素材。

遇到来源冲突时采用优先级更高的来源，并删除无法核实的运行时结论。

## 7. 章节内容

### 7.1 项目概览

- 算法测评优先、多场景算法建设第二的总体定位。
- 测评对象、输入、输出和成功标准。
- 当前能力、已接入领域能力和目标架构的状态说明。
- 管理、研发和操作三条阅读入口。

### 7.2 总体架构与数据流

使用五层架构图：

1. 体验与入口层：前端、CLI 和 API。
2. 控制面：Registry、RunSpec、预检和任务状态。
3. 执行面：数据快照、折内特征、训练和冻结推理。
4. 证据面：PredictionRecord、EvidencePack、排行榜和发布。
5. Battery SOH Domain Pack：数据、特征、曲线和场景政策。

使用一张端到端流程图表达：

资源接入 → 内容摘要 → Spec 固化 → 预检 → 用户确认 → 隔离执行 →
指标计算 → 证据验证 → 排行榜发布 → 前端展示。

### 7.3 SOH 数据、特征与算法

- 默认数据根目录与 `processed/*_features.pkl` 发现契约。
- 统一必需列和结构性缺失处理原则。
- 当前可发现的数据集及数据质量含义。
- `full`、`voltage`、`ic_dva`、`partial_window`、
  `capacity_time` 等特征方案。
- 充电窗口、IC/DVA、HI 三性、因果平滑和特征谱系。
- 线性、树模型、核方法、神经网络、物理残差和 PINN 的原理分组。
- 点估计、不确定度、后处理和周期重标定的职责边界。

### 7.4 公平测评协议与指标

- LOCO、LODO、LCHO 的训练/测试边界和适用场景。
- Training Run、Adaptation Run 和 Frozen Inference Run 的差异。
- 同数据快照、同协议、同 seed、同 held-out 覆盖的比较前提。
- MAE、RMSE、MAPE、偏差、最大误差、PICP、单调性、越界率和 EOL 指标。
- 轨迹级、资产级和数据集级统计单位。
- 排行榜资格、覆盖范围和部分成功语义。

### 7.5 核心契约与证据对象

- RunSpec 与比较键。
- DatasetSnapshot 与内容摘要。
- Target-stripped fold view 与泄漏防护。
- PredictionRecord 与有限值要求。
- EvidencePack 的内容、摘要和原子发布。
- `execution_state`、`outcome` 和 `verdict` 的区别。
- 结构化失败分类和不可变 generation。

### 7.6 前端五页签

分别说明：

- 训练测评：上传源码算法/特征，组合配置，训练执行和 Pickle 发布。
- 推理测评：选择冻结模型和目标数据集，验证迁移精度、延迟和吞吐。
- 模型资产库：模型来源、训练范围、特征契约和推理审计。
- SOH 完整看板：SOH 轨迹、充电曲线、IC/DVA 和高亮特征段。
- 全局诊断：覆盖范围、稳定性、算法 × 特征矩阵和数据 QC。

每个页签包含：

- 适用场景。
- 必需输入。
- 操作步骤。
- 成功信号。
- 常见失败。
- 关联产物。

### 7.7 工具安装、启动与配置

- Python 环境和依赖安装。
- 数据目录配置。
- 后端 API 启动。
- 前端静态服务启动。
- API 健康检查。
- 前后端 URL 参数连接方式。
- 服务停止和端口冲突处理。

命令必须依据当前代码重新核对，不沿用未经验证的旧端口。

### 7.8 新资源接入

- 数据集：Pickle 数据表和列契约。
- 算法：可信本机源码插件接口。
- 特征：列选择或折内 transform 接口。
- 模型：冻结 Pickle 资产、特征契约和兼容性预检。
- 上传、验证、事务激活、失败回滚和目录安全。

### 7.9 训练测评与冻结推理

- 训练矩阵规模计算。
- 深度模型耗时原因。
- 训练完成后的 Pickle 资产发布。
- inference-only 与训练榜的职责分离。
- 模型跨数据集迁移、兼容组合和失败组合。
- 任务状态、部分成功和历史任务重跑。

### 7.10 结果与证据解释

- `results.csv`、`results.parquet`。
- `leaderboard.json`、`dataset_leaderboard.json`。
- `qc_report.json`、`run_config.json`。
- inference benchmark 和 inference run config。
- EvidencePack 与内容摘要。
- 前端 KPI、覆盖范围和验收通过数的正确解释。

### 7.11 同步与离线打包

- 前端数据产物构建。
- 原生 Battery Dashboard 同步。
- Portable 目录包。
- Standalone 单 HTML。
- immutable generation、`CURRENT.json` 和 last-known-good。
- 打包前验证和失败时保留旧发布物。

### 7.12 排障与安全

至少覆盖：

- 数据集未发现。
- 选择数据集后结果不变。
- 训练长期 running。
- 推理按钮无响应。
- 0 个验收通过。
- Pickle 特征不兼容。
- 前端未更新或读取旧缓存。
- 新数据未进入完整看板。
- 页面布局溢出或中文乱码。
- 上传失败和事务回滚。
- 路径穿越、Windows 设备别名和不可信 Pickle 风险。

### 7.13 速查附录

- API 路由表。
- CLI 命令。
- 启动命令。
- 同步和打包命令。
- 关键目录。
- 产物文件。
- 上线前检查清单。

## 8. 视觉系统

采用评测工作台式综合说明书。

### 8.1 色彩

- 深色导航：`#111827` 附近的中性深色。
- 正文背景：白色。
- 页面背景：浅灰。
- 契约和流程：蓝色。
- 通过和证据：绿色。
- 风险和注意：琥珀色。
- 失败：红色。

不使用渐变、装饰性光球或单一紫色主题。

### 8.2 字体

- 中文正文使用系统中文无衬线字体栈。
- 命令、路径、ID 和摘要使用等宽字体栈。
- 不从网络加载字体。

### 8.3 桌面布局

- 左导航约 240 px。
- 中央正文采用弹性列，并限制长文行宽。
- 右侧速查栏约 260 px。
- 导航和速查栏可 sticky，正文独立滚动。

### 8.4 响应式

- 中等宽度时，右侧速查内容进入正文。
- 小屏时，左导航折叠为章节菜单。
- 表格在自身容器内横向滚动。
- 页面级 `scrollWidth` 不得超过 `clientWidth`。

### 8.5 打印

- 隐藏导航、搜索、复制按钮和阅读路径控件。
- 展开全部折叠内容。
- 避免标题与首段分页分离。
- 表格标题行可重复。
- 架构图和步骤图避免被分页切断。

## 9. 交互

- 全文搜索：匹配标题、正文、命令和关键词。
- 目录定位：点击锚点滚动，滚动时更新当前章节。
- 章节折叠：默认展开，用户可手动折叠。
- 代码复制：复制成功提供可访问状态提示；剪贴板不可用时回退到文本选择。
- 阅读路径：高亮管理者、研发或操作路径，不隐藏内容。
- 返回顶部：长页面提供图标按钮和可访问名称。
- 所有交互在 JavaScript 不可用时仍保留完整正文和锚点导航。

## 10. 图文资产

- 使用当前候选前端的真实截图，覆盖五个页签的代表状态。
- 截图包含简短标题、功能说明和所示状态，不依赖截图文字承担全部语义。
- 架构图、Workflow、状态机和证据链使用 HTML/CSS 图形，避免外部图形库。
- 图片压缩后转为 data URI，保证单文件离线使用。
- 不嵌入包含个人信息、令牌、绝对临时路径或敏感运行日志的截图。

## 11. 单文件实现

- 一个语义化 HTML 文件。
- CSS 和 JavaScript 全部内联。
- 图片使用内嵌 data URI。
- 不执行网络请求。
- 不使用构建步骤或运行时依赖。
- 顶部提供文档标题、定位说明和三条阅读路径。
- HTML 源码保持可维护分区，并使用少量说明性注释。

## 12. 错误处理

- 搜索无结果时显示明确空状态。
- 锚点缺失时不抛出未捕获异常。
- Clipboard API 不可用时使用兼容回退。
- 图片加载失败时显示替代文本和边框占位。
- JavaScript 初始化失败不影响正文阅读。
- 打印和窄屏规则不依赖 JavaScript。

## 13. 验收

### 13.1 内容

- 不包含 `TODO`、`TBD` 或占位章节。
- 不显示版本或日期。
- 当前能力与目标能力明确区分。
- API 路径、命令、目录和产物名称与当前代码一致。
- 五个前端页签均有独立说明。
- 训练与冻结推理职责明确分离。

### 13.2 技术

- 文件可直接通过 `file://` 打开。
- 不产生外部网络请求。
- UTF-8 中文显示正确，无替换字符和已知乱码片段。
- 所有目录锚点和内部链接有效。
- 搜索、滚动定位、章节折叠和复制功能有效。
- 浏览器控制台无错误。

### 13.3 视觉

- 1280×720 无重叠和页面级横向溢出。
- 390×844 无重叠和页面级横向溢出。
- 代码、表格和长路径不撑破父容器。
- 前端截图清晰且带说明。
- 打印预览不截断关键图表。

### 13.4 来源

- 说明书正文附“内容边界与来源”章节，但不显示文档版本或日期。
- 来源只列项目内可核验文件和必要的公开参考名称。
- 不使用无法从代码、测试、数据产物或设计文档核实的结论。
