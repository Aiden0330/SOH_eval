## 0. 结论先行（TL;DR）

两份文档在「分层思路、禁随机切分、传统ML/容量侧/C++约束」上与基座一致；但**测评框架与基座的 eval_harness 契约存在三处实质性偏离**，且**忽略了数据层的标签可信度问题**——后者已被实测数据坐实（NASA/CALCE 的 SOH 标签含 0.0 与 1.22 的物理不可能值）。若不修，benchmark 会"在垃圾标签上精确地排序算法"。

## 1. 评估标尺：基座契约（路由确定）

> 这是评估的"标准答案"，全部来自 phm-router 路由到的基座技能，非本次新发明。

**R1 流水线顺序（soh-adapt-v2）**：异构数据源 → 数据统一层 → 容量侧特征 → 传统ML重训 → C++导出 → 三门控。

**R2 规范 Schema + 字段注册（data_unify）**：`t/V_cell/V_pack/I(放电负)/T/soc_bms(禁当标签)/meta{vendor,station,cell_model,C_rated_Ah,topology,granularity}`；**未经映射注册的字段一律拒入特征层**；QC 闸（缺口切段/卡死跳变剔除/零漂自检），通过率 <70% 退回。

**R3 容量侧特征（features）**：禁内阻/EIS/脉冲/dV-dI；按工况可得性分 A/B/C 组；每段输出**可得性掩码**，**可得率 <20% 自动剔列、禁止全局均值填充**（填充值会被树模型当真实分裂点）；无内阻兜底链 = 机会性满充标定事件 → 协变量退化外推 → 超 45 天无标定 `validity_flag=false`。

**R4 重训协议（retrain）**：按数据量选模型（<200 岭+conformal / 200–2000 GPR / >2000 GBDT+分位数）；切分单站时间 70/30、多站留站；**标签仅用标定事件容量，禁用 BMS 自报 SOH**；标准化只在训练段拟合并序列化进模型包；时序 CV 按**标定事件分组**切分（非按行）。

**R5 eval_harness 真·三门（soh-adapt 1.0 §2）**——注意：是**三套数据集**，不是三类检查：
1. **金标回归集**：旧验收场景，适配后 MAE 劣化 **≤ 10%**（防遗忘）。
2. **目标场景留出集**：时间切分后段，MAE **≤ 2% SOH** 且 **95% CI 覆盖率 ≥ 90%**。
3. **物理一致性集**：长序列回放，单调性（允许 ≤0.5% 标定回跳）+ 估计值落 **[0.6,1.05]**，违例率 **≤ 0.1%**（内阻一致项在禁内阻下删除）。

**R6 C++ 导出（cpp_export）**：纯数据+代码生成推理，无 ML 库；Python↔C++ golden-vector 逐条对拍，容差 ≤1e-6（线性/树）/≤1e-5（GPR）；树阈值 `<=` 约定须与 sklearn 一致；版本号编入头文件并随每条输出上报。

**R7 红线（跨技能）**：禁随机切分；**不确定度/CI 不可省（传统 ML 也必须给，否则 G2 覆盖率无法判定）**；未注册字段不入特征层；C++ 侧零训练代码；Schema 变更 = 算法变更须重跑门控。

## 2. 证据：数据现实核查

实测 `data/processed/*.pkl` 的 `soh` 标签：

| 数据集 | cells | rows | soh 范围 | >0.5% 回升循环占比 |
|---|---|---|---|---|
| NASA | 32 | 2723 | **[0.000, 1.222]** | 13.0% |
| CALCE CS2 | 13 | 15411 | **[0.000, 1.018]** | 10.1% |
| HUST | 77 | 146122 | [0.800, 1.120] | 0.0% |
| Oxford | 8 | 519 | [0.616, 0.999] | 0.5% |

- NASA/CALCE 标签越过物理边界（0.0、>1.05），且 10–13% 循环容量回升远超合理再生 → **标签含噪/解析瑕疵**。
- HUST 被截在 0.8 地板、77 颗 LFP，是化学域主力但只覆盖中后段寿命。
- 这些病若不在进 benchmark 前拦下，**所有 RMSE/MAE 排名都被污染**，且 chemistry-out 会把"数据瑕疵差异"误读成"化学泛化差异"。

## 3. 父方案（md）评估

### 强项（保留）
- L1–L6 分层与核心论点（泛化赢在特征/域适配/协议层）正确且论证严密；DL/PINN/集成的选型对比扎实、与硬约束闭环。
- L5 留一域 + 禁随机 K-fold 命中 R7；L3 单调约束**正确地加在吞吐量维而非日历时间**（比基座 1.0 笼统的"SOH 单调不增"更精确，是 md 的亮点）。

### 缺口
- **[P0-A] 落地优先级与强制 CI 冲突**：md「第一批 = L1+L5」**不含 L4 不确定度**，但 R5/R7 要求目标留出门必须有 95% CI 覆盖率——按 md 优先级跑出的"第一批跨域基线"**无法过 G2**。need：把 CI 提到第一批（哪怕只用 conformal 套在点模型上）。
- **[P1-B] 缺防遗忘金标门**：md 的 L5 全是"向新域泛化"，没有 R5 门1"不退化旧验收场景（MAE 劣化≤10%）"的概念。跨域方案尤其容易牺牲主场，缺这条护栏。
- **[P1-C] 标签纪律缺位**：md 未复述 R4"仅标定事件容量、禁 BMS 自报 SOH"；而它想用的 RWTH/M5BAT 场站数据多无容量标签——features.md 那套"标定事件检测 + 协变量外推 + 45 天 validity"子系统 md 完全没提，却是 station 线的前提。
- **[P1-D] 特征可得性掩码缺位**：md L1 列了特征但没带 R3"可得率<20%剔列、禁均值填充、输出可得性掩码"。跨数据集混训（不同工况特征可得性不同）会踩这个坑。
- **[P2-E] 域适配折内拟合**：md L2 CORAL/TCA 对齐源/目标分布，但没声明 DA 必须**只用目标域训练段**拟合——若用到留出测试段统计量即泄漏，留一域协议下尤其隐蔽。
- **[P2-F] C_rated 归一缺位**：md 只提温度归一，没提跨容量电芯的 `Q_win_ah` 等绝对安时特征需按 C_rated 归一（基座 1.0 adapt_cell）。

## 4. soh_bench Spec 评估（自审，对齐基座）

### 强项（保留）
- 模块边界单向无环、TDD 友好；留一 cell/chemistry-out + 禁随机切分命中 R7；estimator `fit(train)` 再 `predict(test)` 的两段式契约**结构上杜绝了测试段泄漏进 fit**（这点是对的）。

### 缺口
- **[P0-1] "区间可选"违背 R7 红线**：spec 选「点估计必需、区间可选、PICP 条件计算」，但基座红线明确"传统 ML 也必须输出 CI，否则 G2 覆盖率无法判定"。**裸点估计的估计器在基座语义下根本不能过门**。当前 spec 把无区间记 `PICP=NA` 当普通缺列，掩盖了"该算法不可验收"这一事实。
- **[P0-2] 真·三门缺两门**：spec 指标集只有 RMSE/MAE/max/EOL/PICP（全是误差），**没有 R5 门1 防遗忘、没有 R5 门3 物理一致性（单调违例率 + 值域 [0.6,1.05]）**。物理一致性门又便宜又是 SOH 必备，且正是能拦住第 2 节那些垃圾标签的门。
- **[P0-3] 数据/标签 QC 门缺位**：spec 的"结构校验"只查 schema 与 NaN/inf，**不查值域、不查单调、不查标签来源**。实测证明 NASA/CALCE 标签越界——spec 会带病算指标。need：loader 前置 R2/R3 QC 闸 + 标签来源登记（禁 BMS 自报）。
- **[P0-4] 化学域混淆**：当前 NASA/CALCE/HUST/Oxford 的化学体系大致是 {LCO, LFP, NMC}，每个化学体系往往**只有 1 个数据集**。leave-one-chemistry-out 实为"留一数据集"，化学效应与实验室/数据集效应完全纠缠——**指标会高估化学泛化能力**。need：每化学体系 ≥2 独立数据集才允许声称 chemistry-out，否则降级标注为"数据集留出"。
- **[P1-G] 三门命名冲突（继承自 md）**：spec §6 套用 md 的 Gate1结构/Gate2数值/Gate3验收，与基座 eval_harness 的金标/留出/物理三门**不是一个轴**。须以基座三门为准。
- **[P1-H] C++ 对拍门未挂**：Q5=边缘，phm-router 要求"门控追加 Python/C++ 输出对拍项"（R6）。spec 无 cpp_export golden-vector 对拍，也无 estimator 可导出性标记。

## 5. 再设计（修订方向）

### 5.1 三门重构（解决 P0-2 / P1-G 命名冲突）

以基座 eval_harness 为权威，soh_bench 暴露**三条评估轴 = 三套数据集**，"结构→数值→验收"降级为每条轴内部的**检查梯度**（不再叫"门"）：

| 评估轴（基座门） | 数据集 | 指标 | 验收（可配） |
|---|---|---|---|
| **G1 防遗忘** | 注册的主场景基线 | 旧场景 MAE 劣化 | ≤ 10% |
| **G2 泛化/留出** | 留一域折（cell/chemistry/station）| RMSE/MAE/EOL区/max + **PICP** | MAE≤2%、PICP≥90% |
| **G3 物理一致** | 逐 cell 预测轨迹回放 | 单调违例率 + 值域∈[0.6,1.05] | 违例率≤0.1% |

检查梯度（每轴内）：结构契约（schema/shape）→ 数值合理性（量程/跨域退化方向）→ 验收阈值。

### 5.2 不确定度强制化（解决 P0-1，同时尊重用户"可选"诉求）

综合方案：**契约要求 CI，但允许裸点估计器以"G2 不可验收"身份上榜。**
- estimator 仍可只实现 `predict`；框架照常算点指标、照常上排行榜的点指标列。
- 但无 `predict_interval` 的估计器在 **G2 标 `gate_eligible=False`**，排行榜显式标注"不可验收（缺 CI）"，而非把 PICP 当普通 NA 掩盖。
- 推荐为任何裸点模型自动套一层 split-conformal（features/retrain 都把 conformal 列为 <200/>2000 数据量的标配）→ 让它们"免费"获得可验收区间。

### 5.3 数据 QC 门前置（解决 P0-3 + P2 数据病）

DatasetLoader 内置 `data/` 前置闸（对齐 R2/R3）：
1. **值域校验**：`soh ∈ [0.6, 1.05]`（可配），越界样本**剔除并计入 QC 报告**，不静默。
2. **标签来源登记**：每数据集在 `metadata.py` 标注 `label_source ∈ {calibration_capacity, bms_reported, unknown}`；`bms_reported` 默认**拒入**（对齐 R4），`unknown` 告警。
3. **可得性掩码**：跨数据集混训时按 R3 输出列可得性，可得率<20%剔列、**禁均值填充**（取代当前粗暴的"列交集"）。
4. QC 报告随 run 落盘（通过率、剔除原因分布），通过率<70%的源标红。

### 5.4 化学域可分性校验（解决 P0-4）

`LeaveOneChemistryOut.generate` 前置断言：每个化学体系 ≥2 个独立 `dataset`；不满足则**拒绝声称 chemistry-out**，自动降级为 `LeaveOneDatasetOut` 并在报告标注混淆警告。→ 触发"补一个同化学体系的独立数据集"的数据待办（ISU-ILCC 补 NMC、SNL/UConn 补 LFP，data/README 已登记）。

### 5.5 C++ 可导出性标记（解决 P1-H，先挂载后实现）

estimator 增加可选 `export_cpp(path) -> None` 能力位；benchmark 增加可选 `--check-cpp-parity`，对实现了该位的估计器跑 golden-vector 对拍（R6 容差）。v1 仅挂载 + 对内置 Ridge 走通一条对拍，其余估计器标 `cpp_exportable=unknown`。

### 5.6 修订后的模块影响

| 模块 | 变更 |
|---|---|
| `metadata.py` | 增 `label_source`、`chemistry`（仍逐数据集核对）、主场景基线注册 |
| `data.py` | 前置 QC 闸（值域/标签来源/可得性掩码），出 QC 报告；取代列交集 |
| `protocols.py` | 增 `LeaveOneDatasetOut`；chemistry-out 加可分性断言与降级 |
| `metrics.py` | 增 `monotonicity_violation_rate`、`value_range_violation`、`forgetting_delta`（金标对比）|
| `contracts.py` | estimator 增 `predict_interval`（强烈建议）、`export_cpp`（可选）、`gate_eligible` 派生 |
| `runner.py` | 三轴评估（G1/G2/G3）而非单轴；conformal 自动包裹选项 |
| `report.py` | 排行榜按三门出 PASS/FAIL + `gate_eligible` 标注 + QC/混淆警告区 |

## 6. 需用户拍板的决策

1. **不确定度强制性**（P0-1）：采纳 5.2 综合方案（契约要求 CI、裸点估计器降级为 G2 不可验收 + 自动 conformal）？还是维持原"纯可选"？——前者推荐，且仍兼容你之前"点估计必需、区间可选"的本意。
2. **v1 范围扩张**（P0-2/3/4）：把"物理一致性门 + 数据 QC 门 + 化学可分性校验"纳入 v1（这三项是拦垃圾标签、防伪泛化的最低限），还是先做纯误差 benchmark、把门留到 v2？——推荐纳入，因为没有它们这版 benchmark 的数字不可信。
3. **金标防遗忘门 G1**（P1-B）：v1 是否要求注册一个"主场景基线"以启用防遗忘评估？还是 v1 只做 G2/G3、G1 等有明确主场景后再加？
4. **C++ 对拍门**（P1-H）：v1 挂载 + 仅内置 Ridge 走通，还是整体延后到部署专章？
